# 小麦土柱实验台

课程作业原型。15 个土柱按采煤沉陷区湖泥、煤矸石、原状土分组，每组 5 柱。原状土在分析页作为比较基线。第 10 cm 和第 25 cm 土层模拟含水率、温度和电导率，第 10 cm 单独模拟孔隙气体 CO₂。土壤 pH 按土层录入播种前及收获后的实验室测定值。

## 在 VS Code 里运行

用 VS Code 打开这个文件夹，在终端运行 `node preview.cjs`，然后打开 `http://127.0.0.1:4175/`。网站只有 HTML、CSS 和 JavaScript，不用安装项目依赖。也可以直接用浏览器打开 `index.html`，部分浏览器会限制本地文件的记录存储。

## 演示流程

1. 开始页面默认选中 B-01。点击总览中的任何土柱，或使用下拉框切换。每 5 秒生成一批数据，模拟时间前进 5 分钟。页面右上角可以暂停。
2. 在浇水提醒中选择按含水率下限或每日定时提醒。含水率提醒以指定深度的连续 3 次读数为准。设置应用于同一处理组的 5 个土柱。
3. 点击「记录浇水」，填写实际水量和备注。在趋势图查看浇水时刻，在「浇水记录」查看前后各 12 次采样的平均值差及浇水后 1 小时内的 CO₂ 峰值和达峰时间。模拟约 1 分钟可累积 1 个实验小时。
4. 在「碳指标」修改各层的 SOC 化验值和干土质量，页面以 g C 显示每柱存量及变化。添加排水的 DOC 浓度和体积，页面以 mg C 加总流失量。pH 变化以 pH 单位计。

演示参数和数据保存在当前浏览器。阈值、处理组和模拟响应仅用来展示功能，后续接入传感器时需要根据实际实验方案设置。孔隙气体 CO₂ 用 ppm 展示，土表排放量需另外测定通量。

## AI 分析

在「AI 分析」页可分析全部 15 柱或当前所选土柱。报告按点击时的模拟时间取快照，汇总最新含水率、温度、孔隙气体 CO₂、EC、与 1 小时前的读数差，以及浇水方案和最近浇水记录。无模型配置时可直接运行本地规则分析。旧供水分组的演示记录仍保留在浏览器原有存储中，新的基质分组使用独立的记录。

接入模型时，将 `.env.example` 复制为 `.env`，填写 `SOIL_AI_API_KEY` 与 `SOIL_AI_MODEL`，在 VS Code 终端运行 `node --env-file=.env preview.cjs`。默认使用 OpenAI 接口。连接其他兼容 Chat Completions 的服务时，设置 `SOIL_AI_BASE_URL` 为服务给出的 API 基础地址。密钥由本地后端读取。配置完成后点击分析，模型服务会收到所选范围的模拟传感器读数、变化量和浇水量。模型请求失败时，页面仍会显示本地分析结果。

`.env.example` 中预填了示例模型 ID，可以换成 API 项目可用的模型。密钥只填写在运行服务的电脑。重启服务并刷新页面后，「AI 分析」页会显示「模型已配置」。点击「分析当前状况」后出现「模型解读」，即可确认模型调用成功。

## 同一局域网访问

1. 在运行服务的电脑上执行 `ipconfig`，找到当前 Wi-Fi 或以太网适配器的 IPv4 地址。
2. 在本项目的 VS Code 终端运行下面的命令，将示例 IPv4 地址替换成上一步的实际地址。

   ```powershell
   node --env-file=.env preview.cjs 4180 --host 192.168.1.23
   ```

3. 让同一局域网里的其他电脑在浏览器打开终端显示的 `Preview` 地址。请保持运行服务的电脑和这个终端开启。只有运行服务的电脑需要 Node.js 和模型配置。

若运行服务的电脑可以打开该地址，其他设备却连不上，检查网络是否允许设备互访，以及 Windows 防火墙是否允许受信任局域网访问 TCP 4180。启用模型时，能访问页面的同网设备也能发起模型请求。该启动方式适用于局域网演示。需要跨网络访问时，将 Node 服务部署到可访问的服务器，并为模型接口配置登录和用量限制。

各浏览器单独保存模拟数据和手动记录。同一台电脑用不同地址打开网页时，浏览器也会分别存储。要让多端读取同一份真实数据，后续需要把采集和记录接到服务器存储。

## 发布到 Render

1. 在 GitHub 新建一个仓库。上传 `package.json`、`preview.cjs`、`index.html`、`styles.css`、`app.js`、`analysis.js` 和 `experiment.js` 到仓库根目录。真实的 `.env` 留在本机。
2. 在 Render 选择 **New → Web Service**，连接该 GitHub 仓库。运行环境选 **Node**，**Root Directory** 留空，**Build Command** 填 `npm install`，**Start Command** 填 `npm start`，**Instance Type** 选 **Free**。
3. 部署成功后打开 Render 显示的网站地址，在「AI 分析」页点击「分析当前状况」验证规则分析。
4. 如需启用模型，在服务的 **Environment** 页面添加 `SOIL_AI_API_KEY` 和 `SOIL_AI_MODEL`，保存并重新部署。如果只想让指定同学访问，可另设 `SOIL_SITE_PASSWORD`，浏览器登录时用户名是 `demo`，密码使用你设置的值。密钥仅供服务器访问模型服务。使用其他兼容接口时可设置 `SOIL_AI_BASE_URL`。
